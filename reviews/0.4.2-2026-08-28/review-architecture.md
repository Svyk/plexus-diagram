## 1. Nest stack models history, but the crumb trail is graph structure
**File:** `src/canvas.js:17`, `src/canvas.js:647-687`, `src/feature.js:234-264`, `src/feature.js:487`
**Severity:** warning
**What is wrong:** `nestStack` is a module-global array. `openNestedDiagram` pushes the parent; `syncNestStackOnNavigate` pops only when the navigated-to page uid equals the top entry. Every other route change (daily page, another diagram, right-sidebar open, browser forward, direct URL, reload) leaves the stack as-is, so the next enhanced diagram anywhere in the app renders `Stale › Current`. Three writers mutate it: feature pushes/pops, `installPlexusDiagram` zeroes it, and the canvas truncates it (`crumbs.length = i`, `canvas.js:672`) before firing `openCrumb` — the view owns navigation state. Separately, `crumbRow` is appended to the toolbar only at construction (`if (crumbs.length) toolbar.append(crumbRow)`, `canvas.js:687`); `renderCrumbs()` runs on every `render()` but a canvas created with an empty stack can never show crumbs afterwards.
**Why it matters:** Nested boards are literal child blocks of the parent diagram block (that is the canonical model this extension is built on). The true breadcrumb chain is therefore already in Roam: ancestors of the current diagram uid filtered by `isDiagramString`. Tracking it as navigation history re-derives, imperfectly, something the graph already knows, and the global makes it wrong across diagrams. It also fails the reload case that the enhanced-uid cache was specifically built to survive.
**What needs to change:** Delete `nestStack`. In `feature.js`, at enhance time, compute `diagramAncestors(uid)` from `roamAlphaAPI.data.pull("[:block/uid :block/string {:block/parents ...}]")` (or `:block/parents` + string pull), filter by `isDiagramString`, map to `{uid, title: parseDiagramTitle(string)}`, and pass the result into `createCanvasRoot({ crumbs })` — the test DI hook `nestStack:` already exists; rename it. Crumb click stays `onPersist({ openCrumb })` → `openCrumb`. Append `crumbRow` unconditionally and let `pxd-crumb--empty` hide it. If a history semantic is ever wanted on top, key it per diagram uid on the session, never module-global.

## 2. Library portal outlives the view that opened it
**File:** `src/library.js:35`, `src/library.js:61`, `src/library.js:18-20`, `src/feature.js:266-297`, `src/view.js:74-79`, `src/lifecycle.js:63-67`
**Severity:** warning
**What is wrong:** The drawer now mounts on `document.body` (correct — it must escape `.pxd-world`'s transform) but is registered with the *extension* lifecycle (`lifecycle.node(drawer, parent)`). Nothing ties it to the view: `mountDiagramView`'s dispose removes the canvas and wrapper only, `pruneDetachedViews` does not know about `activeLibrary`, and `exitFullscreenOnNavigate` leaves it alone. Before v0.4.2 the drawer lived inside `.pxd-root` and died with it; now navigating away with the library open leaves a fixed 320px panel floating over the next page until Close or unload. Additionally: (a) every open pushes a fresh `node.remove` disposer onto the lifecycle array that is never released on close — the closure retains each detached drawer until unload (pre-existing, but now on body); (b) `mountRoot` is dead in a browser (`document.body || mountRoot`), and `feature.js:283` also passes `document.body || root` — the same decision encoded twice; (c) `placeLibraryDrawer` anchors to the *first* `.pxd-toolbar` in the document, which is the wrong toolbar when two diagrams sit on one daily page, and is computed once with no re-place on resize, fullscreen toggle, or sidebar animation — the very signals `applyFullscreenChrome` already observes.
**Why it matters:** Cleanup-ownership table: "DOM nodes you appended — you must remove", at the granularity of the thing that created them. A body-mounted node owned by the wrong lifetime is the classic Roam-extension orphan; it also breaks the "after navigation the native UI is fully restored" acceptance bar without an unload.
**What needs to change:** Make the view the owner. `toggleLibrary` returns the drawer handle and `mountDiagramView` (or the session view record) closes it in its own `dispose`; `pruneDetachedViews` then handles navigation for free. Register one extension-level disposer (`lifecycle.add(() => activeLibrary?.close())`) instead of one per open. Drop the `mountRoot` parameter and the duplicate fallback in feature.js. Pass the canvas's own `toolbar` element (or `root`) into `placeLibraryDrawer` instead of `document.querySelector`, and re-place on `resize` + the fullscreen chrome signals (or position from `root.getBoundingClientRect()` on open and on resize).

## 3. `!important` caret/cursor block breaks the theme contract and ships a private class name
**File:** `src/extension.css:26`, `src/extension.css:30-44`, `src/extension.css:783`, `src/extension.css:786-799`
**Severity:** warning
**What is wrong:** Rule 17: `roam/css` loads after extension CSS and at equal specificity the user wins, by design. Nine selectors carry `caret-color … !important; cursor: text !important`, plus `!important` on `.pxd-root` itself and again in the dark block. Against the stated target (`:root:not(.svy-off-beam) textarea { cursor: url(...) 16 16, text }`, specificity 0,2,1) the extension's `:root:not(.svy-off-beam) .pxd-root textarea` (0,3,1) already wins without `!important`; the `!important` only defeats every *other* stylesheet, including the user's own future `roam/css` and other extensions' dark themes. `.svy-off-beam` is one graph's personal `roam/css` token baked into a published extension. Caret colour is hard-coded (`#1c2127` / `#f5f8fa`) instead of `var(--pxd-text)`, which is why a second 14-line dark block exists — `caret-color` inherits, so the token on `.pxd-root` already covers light and dark. Scoping under `.pxd-root` is right (rule 5 satisfied; `[contenteditable]` only matches Roam editor nodes rendered inside cards).
**Why it matters:** `!important` in a theme-adjacent property is exactly the "generated dark branch you cannot override" trap rule 17 warns about, and a personal class name in the shipped sheet couples the extension to one install. Two duplicate blocks are two places to forget when the palette changes.
**What needs to change:** Remove every `!important` in this block. One rule: `:root .pxd-root :is(textarea, .rm-block__input, [contenteditable]) { caret-color: var(--pxd-text); cursor: text; }` (0,3,1 beats 0,2,1). Delete the dark duplicate at 786-799 and the `caret-color` line at 783. Keep the Beam rationale as a comment phrased generically ("beats `:root:not(.x) textarea` hotspot cursors by specificity") and drop the `.svy-off-beam` selectors; if the user's own Beam CSS needs an opt-out class, that belongs in their `roam/css`, not here. Update `test/canvas.test.js:79-81` accordingly.

## 4. Canvas writes to Roam and reads `location` directly for the nested-name field
**File:** `src/canvas.js:1`, `src/canvas.js:1115-1141`, `src/canvas.js:1128`
**Severity:** warning
**What is wrong:** The "Name this board…" input calls `updateBlock(child.uid, …)` from the view with its own 150 ms debounce, bypassing `NativeDiagramSession` / `DiagramAdapter` (`adoptBaseTree`, echo absorption — battle rule 2). After each write the pull watch replays the change; the code patches `live.string`, `child.string`, `card._pxdString` inside `.then` so `renderCards` skips the repaint, but a pull that lands before the promise resolves repaints the card body and destroys the input mid-typing. To avoid renaming the currently open diagram's own block, canvas now imports `diagramUidFromLocation` — the view knows about routing. `exitEdit` already calls `updateBlock` directly, so this extends an existing leak rather than opening one, but the naming path is new and small enough to do through the session. Unverified: `DIAGRAM_MARKER` accepts `{{[[diagram]]:Name}}`, but nothing in this repo or the roam-plugin-dev KB establishes that Roam's native renderer still emits `.rm-diagram` for the named form. If it does not, `openNestedDiagram` → `waitForDiagramEl` never resolves and a named board can never be enhanced.
**Why it matters:** Rule 2 exists because Roam echoes structural writes back tens of ms to seconds later; every write that skips the adapter is a future "the card blanked while I typed" bug. Routing knowledge in the view is coupling that the `onPersist` action channel was designed to avoid.
**What needs to change:** Add `session.renameCard(uid, string)` that writes through the adapter and re-adopts the base tree so the echo is absorbed; canvas emits `onPersist({ renameCard: { uid, string } })`. Pass "this card is the open diagram" as a flag from `feature.js`/`view.js` (they already know `diagramUidFromLocation`) rather than importing discovery into canvas. Live-verify the `{{[[diagram]]:Name}}` form on Svy before shipping more on top of it; if native does not accept it, store the title as a metadata `title::` row or a first child block instead.

## 5. Edge creation is spread over four sites; the view reaches into `session.model`
**File:** `src/view.js:46-53`, `src/canvas.js:1555`, `src/canvas.js:1571`, `src/session.js:121-128`
**Severity:** suggestion
**What is wrong:** `settings.get("connector-style") || "bezier"` is repeated in canvas (twice), view.js, and implicitly in `session.connectSelected`. `view.js` calls `session.model.addEdge` directly and then `session.persistLayout()` — a second serialized metadata write immediately after `addCard` already persisted the layout. `canvas.completeConnect` for card→card sets `layoutDirty = true; await flushLayout()` directly, bypassing `markLayoutDirty` (fine, intentional) but again owning edge semantics in the view.
**Why it matters:** The session is supposed to be the only thing that mutates the model *and* persists; when `addEdge` gets a real home (metadata-only edges becoming native `:diagram/edges`, or label defaults) there will be four places to change. Two persist writes per gesture is the exact "sync silence"/write-minimization concern v0.4.0 fixed for viewport.
**What needs to change:** `session.addEdge(source, target, kind?)` owning the kind default, dedupe, `persistLayout`, and `notifyViews({ type: "edge" })`; `session.addCard(string, position, { edgeFrom })` so connect-to-empty is one queued persist. Canvas and view then only emit actions. The card-as-diagram-child decision is correct — keep it.

## 6. `parseDiagramTitle` and crumb state live in the view module
**File:** `src/canvas.js:17-25`, `src/canvas.js:650`, `src/feature.js:21`
**Severity:** suggestion
**What is wrong:** `feature.js` (controller) imports a string parser and navigation state from `canvas.js` (view). `parseDiagramTitle` belongs next to `isDiagramString` / `DIAGRAM_MARKER` in `discovery.js`. `if (Array.isArray(crumbRow.children)) crumbRow.children.length = 0;` is a test-stub accommodation in production code.
**Why it matters:** Dependency direction is the only thing keeping `canvas.js` (1.8k lines) from becoming the place everything lands; the stub hack means the DOM stub, not the code, is what is wrong.
**What needs to change:** Move `parseDiagramTitle` to `discovery.js`; crumb data comes from feature (see #1). Fix the test DOM stub so `innerHTML = ""` clears `children`, and delete the guard.

## 7. Capture-phase focus/scroll guard on `document`
**File:** `src/canvas.js:1048-1072`
**Severity:** suggestion
**What is wrong:** Attached in `enterEdit`, detached in `exitEdit` and `dispose` — lifecycle is correct. `stopImmediatePropagation` on capture-phase `focus`/`scroll` for the outline textarea with the editing uid silences every other listener (Roam's, other extensions') for that event. Blast radius is one uid while editing, so acceptable; noting it because it is a host-event intercept, which the battle rules do not currently document.
**What needs to change:** No code change. Record it as a deliberate host intercept in the KB session-learnings so a future "Roam stopped scrolling to the block" report finds it.
